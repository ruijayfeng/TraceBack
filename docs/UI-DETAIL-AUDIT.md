# TraceBack UI 细节审计（v2.1）

日期：2026-10-28 · 分支：`pr/ui-optimization` · 方法：生产构建 + 真实 demo API，Chrome，1440/1280/1024/768/390 五档宽度；逐页截图 + computed style 采样 + axe + taste-skill inspector。

> 这份文档记录的是「布局 / 标签 / 层级 / 字体 / 比例」的逐项检查，而不是功能清单。每条都附改动前后的可测证据。

## 4. 表格与数据密度

- 身份块从「标题 + ID + meta」三行改为「标题 + 状态行 + ID 行」，状态行含 severity/类型/状态/链，避免 ID 行被挤换行。
- 实体最多 2 条 + 「另 N 个实体」；1440 行高从 94/121 降到 87/91。
- 表格 `td` padding 11→9，line-height 1.5→1.45；表头 padding 9→8。
- 数字/时间统一 `tabular-nums`；时间列内容由「UTC 后缀 + 双完整时间」改为「起 + → 止」。
- 1024/768 不再硬塞 6 列，改用两行列表；390 行高 92，1024/768 行高 70。
- 表格模式（≥1281）首列 sticky，横向滚动时身份列不丢。

## 5. 组件与可访问性

- **axe**：`e2e/a11y-axe.spec.ts` 覆盖工作台/详情/证据抽屉/欢迎页；修复选中行 4.02:1 对比度、欢迎页重复 landmark；当前 0 violations。
- **焦点**：抽屉关闭按钮是第一个可聚焦；表格行可 Tab/Enter；页内导航 scroll-spy 改为基于滚动位置的精确计算（原先在时间线处仍高亮「证据」）。
- **print**：payload 裁剪时误删的打印样式已恢复（隐藏 chrome、保留证据文档）。
- **reduced-motion / forced-colors**：保留 v1 的全局降级与结构边框。

## 7. 已知未解决

- AI 报告里的 claim 文本来自确定性模板，包含原始 `entity_id`/JSON 片段；这是数据层事实，UI 不做改写（只做截断和折叠）。
- 真实 AIT-ADS 45k 数据集仍未接入，阈值/列宽/性能只在合成快照与 300 行压力测试下验证。
- 深色模式未做；PR 与上游 `#1`（v0.1.0 staged analysis shell）的冲突尚未解决（见 PR 评论）。
- WebKit/Firefox 自动下载仍受阻，只在 Chrome 验证。
